# Numbered durable ESM-2 attempts

The v2 complete-job protocol executed the real peer-reconstructed ESM-2 model
through Doppler's public operation interface. One completion was dropped, the
provider object was replaced, and a second delivery recovered its saved signed
result from native IndexedDB. There was one remote model calculation. All eight
frozen CPU reference checks passed. The signed job binds its numbered attempt,
exact model, empty adapter set and immutable operation/job policy snapshots.

The retained journal reports one completed attempt and 283,921 serialized bytes.
The loaded-model remote job, including retry, took 2,061.2 ms. All 549 served
Doppler runtime files match the retained 0.6.0 candidate package with SHA256
`95d722c5d3ae10b60e78cd9c8c2ce3a769ecb39229c7f25c1d26a8bf7bee6b10`.
This candidate identity does not claim npm publication.

The separate browser attachment uses synthetic model output and replaces the
entire Chromium process in six cases: completion, failed send, acceptance before
execution, generation, cancellation before delivery and an in-flight acceptance
transaction. It counts actual calls into the substituted operation method.
An acceptance write interrupted before commit may roll back; the replacement
may then execute. If it committed, the replacement fails the interrupted attempt
without executing again. The other cases replay the retained result or terminal
failure without a new calculation.

This experiment used one internally operated physical computer. The real-model
recovery replaced the provider object within the browser; whole-process recovery
is a separate synthetic-model observation. Neither proves independent machines,
independent operators, immediate GPU termination, exactly-once physical execution,
useful history, adapter execution or a public release installation.

## Reproduction

`index.json` hashes every retained file and identifies the two unchanged external
weight shards. `episode.json` binds exact model identity, custody faults, original
host disabled, remote assignment, reference comparisons and runtime sources.
Source patches apply to the recorded repository revisions; this is an explicitly
modified source-tree observation. Private signing keys are not retained.

Verify the archive with:

```bash
npx vitest run tests/unit/retained-peer-pack-episode.test.js
```

To repeat the GPU run, reconstruct `pack/` with the indexed weight URLs and
digests, apply the recorded source patches, install the exact candidate package,
and copy the episode configuration with local paths and a new output directory.
Then run `node scripts/verify-peer-pack-execution.js --config <configuration>`.
Browser flags and executable identity are recorded in the episode. The archive
is inspectable without claiming that its absolute development paths work on
another installation.

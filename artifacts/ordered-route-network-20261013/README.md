# Authenticated route-bound channels

Component: existing partition network owner. Intent adds explicit ordered channel setup; legacy channel setup is unchanged.

`createPartitionNetwork({label:'reploid-partitions-ordered',ordered:{maxRouteBytes,validateRoute},...})` accepts `connect(transportId,{route})` and `retire(transportId,{route})`. Connections are keyed by the complete immutable route and authenticated transport. Multiple routes to the same participant retain independent endpoints. The existing `maxPeers` limit bounds total channels, including incomplete handshakes; no allocation limit is increased. Host callbacks validate provider plan and actual own-stage metadata. Setup is not an execution grant.

Before endpoint creation, the network bounds the setup text before parsing, validates route structure, authenticates the existing RTC certificate binding, invokes host route validation and rechecks certificate strings snapshotted before awaits. The response must echo the exact requested route. Stalled authentication/validation is bounded by the existing setup deadline; late completion cannot construct an endpoint. `createEndpoint` receives the validated route, participant and transport IDs. No singleton route or caller-selected participant bypasses transport authentication.

Retirement calls the named endpoint's cleanup owner before removing its channel. A failed cleanup remains charged and prevents replacement; explicit retry may settle it. Socket closure invokes cleanup but is not proof of resident release. Healthy routes remain available when another retires or fails cleanup. No new scheduler or direct-adjacent transfer is introduced.

`tests.txt` covers 11 new controls plus 42 legacy API tests. It includes simultaneous routes to one participant, immutable caller input, host-stage rejection, changed acknowledgment, setup allocation limits, actual existing binary transport after handshake, bounded missing/stalled setup, cleanup failure/retry and survival of another route. `certificate-before.txt` retains the reproduced same-object certificate mutation vulnerability in the initial new code; the implementation now copies both certificate values before awaiting external ports. `missing-test-channel-properties.txt` retains a harness failure: its initial fake RTC channel omitted ordered/reliable metadata required by the real binary transport. The fake channel was completed; production checks remained strict. Authentication itself is injected in these transport tests; real signatures are covered separately by the peer/chat composition receipts.

Actual Verification Worker, library declaration checks and component charters pass; warnings are retained. No GPU, accepted pin, served application, process or deployment changes. Automatic host composition and physical N-stage acceptance remain separate gates.

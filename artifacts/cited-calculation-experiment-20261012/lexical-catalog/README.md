# Source-exact literal catalog control

Pre-output artifact-only candidate. The preceding worked-contract control produced valid JSON but invented/incorrectly typed operands and reused passage IDs as aliases. This candidate removes operand transcription from the model's job. It cannot remove the model's responsibility for correct operation selection, conditions, contradictions and cited answers.

`catalog.js` is a new bounded lexical enumerator and operations-only adapter. It reuses the existing `sourceMap`, calculator and authorized tool runner. `GRAMMAR.md` declares supported syntax and explicit rejections. Catalog values receive no semantic labels, and no expected case totals enter model input. Original case messages stay unchanged in the fixture; the executed prompt appends a clearly delimited catalog data block to the last user message. That same catalog is charged again when the original history and actual tool result are supplied to the second call.

The original seven cases, ordered corrections, full review criteria, source checkpoint, generation settings and limits remain unchanged: two model calls, one tool attempt, 4096 generated tokens, 8192 prompt-plus-generated tokens including repetition, 16000 raw UTF-16 units and a 1536-token extraction cap. Stop after the first completed structural/tool/budget failure; otherwise complete the seven and independently review all factual requirements. No retries, hidden output repair, generated-answer rewrite or production integration.

`holdouts.json` freezes two additional unrelated cases, including a correction history, before output. They remain locked until the original seven pass full manual review. A successful parser or arithmetic operation alone does not unlock them or qualify the model.

Source tokenizer/evaluator identities, deterministic catalog identities, exact token preflight and independent review must be retained before model generation. Runtime checks bind actual evaluator/loader/reused code, template, tokenizer configuration, and executed prompt IDs. Model generation runs only on x128 CPU with four threads at nice 10; no GPU or inference performance claim.

Component: document tool protocol. Intent preserved. Boundary effects: diagnostic artifacts only. No runtime/model/precision/pin/deployment change.

# Source-scoped operation selection

Artifact-only candidate following the rejected lexical-catalog run. That model mixed competing bids, added included allowances, selected incompatible date operands and repeated an operation without closing its call. Its exact official template and token admission were already verified. This experiment changes subtask scope; it does not treat parser validity as factual accuracy.

For each document, in original order, give the unchanged user questions and that document's exact passages, plus its original catalog aliases and user-constraint aliases. Other documents retain their IDs/names with empty passage arrays. Assistant claims are excluded from these primary-source calculation subtasks, as they already are from the literal catalog. No source clause, amount, alias or tool operation is rewritten. The existing strict official parser and Calculate handler execute one original model-selected plan per source; cross-source operands and forward references fail. No default operation is invented.

The final answer call receives the exact complete original ordered conversation, including earlier erroneous assistant responses and the correction request, followed by the exact generated calls and their actual scoped tool responses. All seven original cases and full factual/citation criteria are unchanged. Original two unseen holdouts remain locked until all seven pass manual review. No new model, seed selection, numerical changes, production prompt/pin changes or generated-answer rewriting.

Aggregate limits remain 4096 generated tokens, 8192 prompt-plus-generated tokens and 16000 raw UTF-16 units. The original 1536 extraction-token allowance is divided evenly across source calls (512 each for three documents). The total operation limit remains 30. Every repeated input, generated call and final answer is charged; actual tool responses are included in final input admission. Stop at the first structural, tool, natural-completion or budget failure, marking remaining source calls/cases unrun. Otherwise complete all seven for independent full factual review.

The initial projection retained assistant history in every subtask and failed preflight: the longest correction required 9442 prompt tokens before generation. `scope.full-history.js` and `token-preflight-full-history-rejected.json` retain that preparation failure. The primary-source projection's prompt lower bounds are 1721–6352; the longest has 1840 tokens left before actual tool-output duplication and answer. This is admission headroom, not evidence the model can finish. No budgets were raised.

`scope.test.js` tests unrelated source spans, preserved IDs/negations/conditions, assistant exclusion, conflicting identity rejection and forbidden cross-source/forward references using the real calculator. `budget_test.py` checks repeated-input and all-output accounting. The actual Verification Worker parses the JavaScript candidate. Source loader/evaluator, original checkpoint/template, reused handler, seven histories and all freeze files are bound before CPU generation on x128, four threads at nice 10. No GPU or performance claim.

Component: Reploid document-tool experiment. Intent preserved. Boundary effects: diagnostic artifacts only. Production adoption requires useful complete cited answers, source then converted qualification, and actual application input replay.

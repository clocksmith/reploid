# Composition boundary after seven monetary decisions

This is a proposal, not another frozen or executed treatment. The seven-decision result is rejected: only the three quote-introducing occurrences received their correct roles. The model confused two deposit bases and an included allowance with quoted prices, then confused an explicit additional charge with an included allowance. The calculator must not consume these labels.

## What a complete workflow needs

Reuse the existing source map and lexical catalog to retain occurrence IDs, exact source passages, monetary and percentage lexemes, dates, and user-stated budget. Never use previous assistant claims as evidence. Model-selected roles remain separate from those lexical facts.

1. Admit a single price relation per exact occurrence. Preserve separate occurrences of equal amounts; a deposit basis cannot introduce another price total. Invalid or conflicting selections leave the affected result unresolved. The current seven-role candidate fails this prerequisite.
2. Select source-backed links for percentage-to-basis, extra-charge conditions, explicitly stated credits, and budget scope. Do not infer that a condition holds merely because an amount is an additional charge. Preserve excluded and included items separately. Require each selected link to reference actual supplied facts/passages; full factual review must still establish entailment.
3. Pass only admitted fact IDs and operations to the existing `source-ledger/adapter.js` and `calculate.js`. Addition, subtraction, percentage application and calendar duration use those supplied values. No case totals, contractor names, deadlines or expected deposits appear in implementation. Unsupported units and missing/conflicting operands remain unresolved; the calculator does not infer them.
4. Preserve quoted estimates, promises and source-bound conditions on derived dates and amounts. A quoted price is not an all-in total. The existing renderer can expose source-backed values and unresolved fields, but cannot establish that omitted conditions are absent.
5. Restore the exact original ordered conversation for a final response consuming the actual admitted ledger. Count that full prompt, all earlier prompts, every generated token and actual tool-result growth against the original 4,096 generated / 8,192 charged / 16,000 UTF-16 caps. Reject before a call lacking headroom. Evaluate the full unchanged factual/citation/follow-up tasks and locked holdouts; no metadata-only pass substitutes for those gates.

The observed money stage cost 2,938 charged tokens across seven calls. The retained first-case empty-result final prompt costs 878, leaving at most 4,376 for every missing semantic link, actual tool-result growth and final generation. This is only an accounting ceiling. No complete workflow admission or latency/usefulness claim is established.

## One next hypothesis for review, not launch

The classifier receives the entire comparison question in every local occurrence request. That global task asks for quote costs, while the frozen local definitions require classifying the particular occurrence, including deposit-only occurrences. In the retained trace, all seven labels were available and the raw semantic winner was unchanged by masking; the dominant `quoted_total` answer therefore did not result from excluding the correct label. This suggests testing whether global question context is distracting the source-local role decision. It does not prove that explanation.

A bounded contrast would remove only the global comparison question from these source-local metadata requests, retaining every exact passage, occurrence offset, seven definitions, model, policy, syntax and predeclared source order. Original question/history remains authoritative for the final complete task. A fresh unrelated occurrence set must be frozen before that treatment's output, with deposit bases, already-included amounts, additional costs, unit prices, paid credits and ambiguous language. No relation is prefilled, masked by source type, selected from expected answers, or repaired. Exact tokenizer preflight must include that treatment's full aggregate composition before calling it an end-to-end candidate.

This contrast requires coordinator selection and a separate freeze. It is not a reason to rerun the current rejected configuration, weaken the factual rubric, or add correct-looking arithmetic to wrong roles. No additional model call has been made.

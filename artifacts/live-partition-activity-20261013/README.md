# Live measured ordered-route activity

The first missing connection was the ordered runner: it measured every stage using one coordinator `performance.now()` clock but returned those observations only in its terminal result. The authenticated entry channel had no activity event, so the workspace and existing activity UI had no timings while generating.

The same runner now emits an incremental aggregate after each completed token traversal. No extra numerical work is submitted. The ordinary ordered chat forwards the exact route/attempt, each ordered stage's count and accumulated measured duration. An explicitly requested `reploid.partition-activity/v1` observation piggybacks on the existing authenticated delta frame or final response when sampled tokens decode to no text; there is no additional activity RPC or acknowledgment. Then `onActivity` updates only the active workspace attempt's execution projection. Older requesters without this event opt-in remain silent. Canonical publication and response text are unchanged.

Validation binds the complete route and attempt, contiguous producer sequence and increasing coalesced receiver sequence, complete ordered stage set, count consistency, finite nonnegative durations and monotonic totals. Final execution must agree with observed aggregates. Late callbacks cannot update a completed/cancelled attempt; telemetry contains no candidate text and performs no publication transaction. Times include coordinator-observed runtime/transport overhead and exclude queue wait; no clocks from different hosts are compared. Reported remote values are not hardware attestation.

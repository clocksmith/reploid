# Installed native resident fixture preparation

Component: physical resident qualification fixtures. Intent preserved: the same
public resident operations, frozen messages/tokens, tensor forwarding and full
logit comparison run through either a browser or an installed Node/Dawn host.
This checkpoint proves CPU contract behavior only. It does not qualify native
numerical output, signed opening, acquisition, an ordinary CLI journey or release.

The optional `REPLOID_NATIVE_EXECUTOR_WS` selects an explicitly owned loopback
Node inspector. `native-partition-process.js CONFIG.json` verifies the standard
native application's delivery members and every installed Doppler archive member
before exposing the fixture port. It reuses installed `createNativeGpuHost` and
public runtime imports. Startup does not open a GPU. The controller opens it only
for physical execution. Actual mapped native libraries are hashed after opening.
Failed resident cleanup remains failed; no released-provider claim is fabricated.

Required JSON configuration: `applicationDirectory`, `nativeDeliverySha256`,
`providerModule: "webgpu"`, and `testDelivery` containing `root`, `bindingPath`,
`bindingSha256`, `archivePath`. Launch with an owned loopback inspector:

```
node --inspect=127.0.0.1:PORT tests/fixtures/native-partition-process.js CONFIG.json
```

The existing browser fixture retains both placements and reference traversal.
`REPLOID_DIAGNOSTIC_PROMPT=2` without `REPLOID_DIAGNOSTIC_STEP` selects the entire
original third request without extra boundary capture or unsplit diagnostics.
It cannot qualify the complete 55-prefix corpus on its own.

CPU validation: 48 focused controls in `cpu-controls.log`; actual Verification
Worker receipt `worker.json` uses the existing `/testing/` capability for these
Node-capable test fixtures, not production browser authority. No GPU was opened
by these tests. The controls include a real owned Node inspector and lexical
resident-opening observation using synthetic modules, failed cleanup, and byte
transport. `verify-worker.mjs` reproduces the Worker check.

Node inspector lacked a dynamic-import callback; a symlinked module URL missed a
lexical breakpoint. The final adapter uses an actual ESM-owned import port and
real runtime URLs. These were harness failures, not model outcomes.

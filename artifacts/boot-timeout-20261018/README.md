# Reploid boot timeout repair — 2026-10-18

Component: public route startup and requester history. Intent preserved; no component authority changes. Doppler remains the owner of metadata hashing; Reploid bundles its installed public helper rather than maintaining another implementation.

## Reproduced defects and repair

Before this change, two new browser regressions failed ([before.log](before.log)): stalled Doppler module downloads prevented history from opening, and initialization could hang after the bundle had loaded without reaching the startup timeout.

History now uses the generated, import-free `metadataDigest` helper from the installed `doppler-gpu/partitions` export. This removes the inference graph from history startup while preserving the same digest implementation. The existing sync/check script verifies generated bytes and records package provenance.

The existing 10-second timeout now covers bundle import and initialization on both public entry pages, plus root service-worker cleanup on `/`. Timeout aborts the pending shell so a late host cannot overwrite the failure screen. Exactly one automatic recovery remains. Limits were not increased. Static entry-script dependency downloads are outside this timer.

The earlier intermittent live timeout lacked a network trace. These are demonstrated startup failure modes, not proof of the sole cause of every historical timeout.

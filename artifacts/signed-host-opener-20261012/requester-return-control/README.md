# Existing-UI basic distributed chat controller

Prepared v7 successor to the retained v5/v6 controls. Tooling only: served application and runtime bytes are unchanged, and the useful signed conversation has not run.

Default `run.mjs` uses `plain-chat.json`: one short filter/map coding request, then a history-dependent follow-up using the actual first answer. Two sends, no automatic retry, no attachments. Full code/example/follow-up correctness requires independent review. Transport completion never establishes answer correctness; wrong complete code is a model-quality failure, while interrupted/failed execution or a deadline is not evidence of a wrong model answer. Maximum-token stopping and unknown cleanup fail lifecycle acceptance.

The existing composer, Copy response and thread picker are used. The read-only CDP helper calls the actual host `getState()`/`getDraft()` so it supports legacy and transactional history without treating old localStorage bytes as authoritative. Streaming samples pair committed/ephemeral host projection with the visible message body, retaining message/attempt IDs. The real clipboard must match the first stored response. After saving an unsent draft, reload selects the existing thread through the UI, waits for rediscovery and checks unchanged messages/attempts/publication digests and no running attempt for 3 seconds. This is a bounded observation, not proof about all future dispatches. If a harness deadline closes an active requester, settlement remains explicitly unknown.

Run from Reploid with `REPLOID_SIGNED_APP_DIRECTORY` naming the frozen application directory (including its private room file), `REPLOID_REQUESTER_FREEZE` naming exact nativeArtifact/browserBundle/runtimeArchive/modelIdentity JSON, and `REPLOID_REQUESTER_REPORT` naming a new output file. `REPLOID_SIGNED_APP_ORIGIN` defaults to isolated loopback port 29670. No room token is committed. The served descriptor must match; the existing full browser-bundle verifier separately owns complete asset hashing. An explicit `REPLOID_REQUESTER_MODE=ready` selects the separately labeled READY route/history control, which never qualifies useful chat.

The read-only CDP observer uses existing host owners to inspect custody receipts, received bytes, pending work and verified files before/after use and after reload. This complements HTTP weight-request observation instead of treating HTTP alone as proof of no peer transfers. Missing observation fails rather than becoming zero. A fresh GPU-disabled browser control records zero custody in `fresh-observation-control.json`. The same observer returned 32 receipts / 32 verified files / 143,254,528 received bytes on the prepared Mac contributor, establishing a nonempty control. Those bounded retained receipts do not measure its entire historic transfer total.

Focused preparation controls: 15 pure receipt tests reject cutoff, output cap, unknown cleanup, hidden fallback, substituted history, invisible/terminal-only streaming, wrong Copy, missing custody, changed reload history, redispatch, short observation and lost draft. A synthetically wrong answer with complete lifecycle still remains semantically unqualified. Actual Verification Worker analysis passes with zero errors/warnings.

`room-observation-control.json` verifies host state/draft persistence and zero new attempts/weight custody in a fresh GPU-disabled browser against the old frozen 7f8e435b snapshot. It joined only the authorized private room, typed an unsent draft, and reloaded; no Send, contribution, model execution or GPU workload was requested. This snapshot used legacy storage: transactional browser acceptance still awaits the new candidate. The first no-room control could read chat state but failed because custody had not been created; `no-room-observation-failure.json` retains that failure instead of inventing zero custody.

Owners: `self/ui/pool-home/conversation-workspace.js` renders/composes and copies; `self/host/chat-session.js` supplies state/drafts; `packages/reploid/src/chat/workspace.js` owns attempts/ordered history; `workspace-history.js` owns transactional records; partition execution owns route/settlement; Doppler owns model execution. No owner is bypassed or replaced by this controller.

Component: acceptance tooling. Intent preserved. Acceptance evidence: focused CPU checks, actual Verification Worker and GPU-disabled no-send control only. Boundary effects: none. New signed useful-answer release acceptance remains pending its frozen candidate and physical window.

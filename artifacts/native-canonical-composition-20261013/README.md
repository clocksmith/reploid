# Native canonical opt-in and durable process ownership

Component: native participant composition and automatic partition retirement. Intent preserved: hosts supply identity, persistence, consent and cleanup; the installed Doppler provider owns generation/state transitions. This is source/CPU contract evidence, not native GPU or installed canonical qualification. No runtime archive, accepted pin, catalog, public contributor or deployment changed.

`createNativeParticipant({canonical:{epochDirectory}})` and CLI `--canonical` require a declared catalog `canonicalGeneration` and the actual installed canonical codecs before connecting or opening a provider. Default participation remains legacy. The current accepted installed package rejects opt-in; `runtime-inventory.json` records its missing exports against the separately identified Doppler source implementation, required resident methods and execution bindings. A new exact standard runtime archive and actual physical qualification are still required.

The native SQLite journal uses the existing Node >=22.13 host requirement, private files, `BEGIN IMMEDIATE`, `synchronous=FULL`, and a bounded busy wait. A process claim rotates both epochs only when no resident ownership is outstanding. A resident owner is recorded before preparation, remains recorded across failed cleanup/restart, and is cleared only by its successful cleanup. Epochs fence execution and stage signing before and after asynchronous operations; explicit attempt/resident cleanup remains possible. This journal does not establish physical GPU accounting across processes or recover an unknown prior resident automatically.

A lost COMMIT acknowledgement rejects the operation. Explicit settlement retry can confirm only that exact owner's committed settlement through a separate SQLite reader; a different owner or replaced revision cannot clear debt. Unknown acquisition/claim outcomes remain closed to admission. No pending marker is erased merely because a process restarted.

Native close preserves source lifetime ordering, attempts all cleanup owners despite synchronous failure, retains the epoch handle while partition retirement failed, coalesces overlapping calls, and retries failed owners while preserving successful ones. Automatic partition and discovery owners now also permit explicit retry after rejected cleanup.

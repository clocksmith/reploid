# Existing active-cleanup controller: optional signed candidate

This is runner readiness, not a physical pass. No candidate was launched or signed.
The original controller, output and pinned-manifest default remain reproducible.
The optional mode is one browser output contributor plus an existing ordinary
requester and independently prepared input contributor. It does not qualify the
native placement or replace the independent numerical evaluator.

## Commands and prerequisites

Produce genuine reports first. The current archive8 binding is
`doppler/artifacts/paired-intermediates-20261012/first-prefill-norm-boundary/archive-8-binding.json`,
archive SHA256 `8ea1767fb61d9009dd257c4065a6acfdbaaf80fa733145898307ed35da0e7f20`.
Its `qualified: false` is historical and must not be rewritten. A passing first
prefix is not a passing 55-prefix/platform qualification.

Rig consumes already-retained independently derived qualification reports; the
controller does not generate them. Existing producer command, from Doppler:

```sh

  --model-dir /ABS/model --manifest /ABS/model/manifest.json \
```

These paths are placeholders for actual evidence, not supplied passing fixtures.
Reports must use Rig's existing resident report/contract shapes, exact manifest,

have actual evidence. Failed comparison reports cannot be used. Source quality,
release authorization and applicable lifecycle gates remain separate.

Freeze a run config before observing physical output. Every file binding is
`{ "path": "/absolute/path", "sha256": "sha256:..." }`. Required config fields:

  `requesterCdp`, `inputPeer`, new absent `profile`, new `output`, `modelId`,
  `sourceCommit`, `surface: "browser-webgpu"`, `partitionIndex: 1`.
- `archive`, original `archiveBinding` (its existing `archiveSha256` and
  `manifestSha256` remain **raw hex**), `application` (complete generated browser
  descriptor), `catalog`, embedded `capsule`, `manifest`, `contract`, `reference`,
  `evaluator` file bindings.
- `qualifications`: at least the actual input/output report bindings. Each has
  `report`, `capture`, `provider`, `partitionIndex`, exact
  `initialExecutionIdentity`, and frozen `providerFields.adapter` and
  `providerFields.libraryIdentity`, each `{path:["actual","field"],expected:...}`.
  These paths refer to existing retained observation shapes, not rewritten
  reports. Declare expected provider identities before physical observations;
  this consistency gate cannot prove that a self-authored receipt is truthful.

Preflight checks complete local delivered assets against the candidate archive
using the existing hosting verifier, not just `pin.integrity`. It checks exact
retained hashes, unchanged bounds, signed target/evidence/identity bindings and
provider observations. Signature trust and release admission remain the actual
runtime's responsibility. No preflight result grants numerical qualification.

Run from Reploid, after coordinating the physical GPU and existing requester:

```sh
node artifacts/cleanup-failure-20261012/active-controller.mjs /ABS/frozen-signed-run.json \
  > /ABS/new-signed-control.log 2>&1
```

It uses ordinary UI contribution/disclosure/Retry. Before exercising cleanup, it
requires the actual host to report signed Capsule opening, signed piece-index
scope, exact model/plan, nonempty verified assigned ranges and fresh acquisition.
It rejects reused contributor profiles. It then rejects one armed close before
releasing resources, checks blocked replacement, explicitly retries stopping,
prepares replacement, obtains new disclosure approval, preserves the earlier
partial answer and unrelated history, and confirms final settlement. Requesters
must request zero weight files. Physical failure receipts remain separate from
preflight, numerical and quality results.

## Validation and limitations

`node --test artifacts/cleanup-failure-20261012/signed-preflight.test.js`:
13 synthetic CPU controls passed. They create no cryptographic qualification and
launch no browsers. `signed-preflight-tests.log` retains results. Existing hosting
checks pass, including changed vendor bytes despite an unchanged pin;
`signed-hosting-tests.log` retains them. Controller syntax passes.

The actual Verification Worker parses the new preflight without errors, but
rejects the existing trusted packaging tool's `node:child_process` use and its
`process.exitCode` assignment (matched as `process.exit`). This existing scope
limitation remains recorded in `signed-runner-worker.json`; the validator and
subprocess ownership were not changed. No blanket Worker pass is claimed.

# Automatic multiuser route isolation

Component: the existing automatic ordered participation, discovery, grants, entry, chat, peer and route owners. Intent preserved. This control uses real protocol owners and WebCrypto grants, with injected certificate verification, in-process ordered channels and numerical stage implementations. Its coding and explanation responses are fixture data. It establishes neither useful-model answers nor physical capacity, durable publication, installed-package acceptance or deployment.

The same declared three-stage model has two coordinators and separate middle replicas sharing one final resident. Two weightless requester owners submit distinct Python-code and closure-explanation prompts. An additional middle replica joins during execution. The control exercises:

1. Cancel the coding request after one observed delta, await actual private-state settlement, and complete the unrelated explanation without closing shared weights.
2. Withdraw the selected coding-route middle contributor during a second pair of conversations. Retain its partial output and complete the explanation on the other route.
3. Discover the newly available replacement, request fresh explicit approval for its exact recipients, and execute a separate coding attempt. No old partial is appended to the retry.
4. Verify no explanation input reached the coding coordinator, no coding output appears in the explanation, requester model-loader calls remain zero, unaffected contributors load once, and all private states settle.

This is eight logical participants in one test process: six possible contributor owners and two requesters. The direct discovery graph distinguishes the two entry points; it is not evidence of autonomous cold stage assignment, demand-driven replication or cross-process GPU accounting. No further streamed deltas may appear after cancellation. Transactional publication is not exercised by this ordinary branch.
